# 指导文档模板

输出文件：`{模块根}/.module-guide.md`

**硬性要求：全文不超过 100 行。超出时压缩表达，不截断内容。**

---

```markdown
# {模块名} 开发指南

> `{path}` · {lang} · 生成于 {YYYY-MM-DD}

## 核心约束

{模块中必须被保留的不变量。写成可验证的规则，每条附代码位置作为依据。}

- `{文件:行号}` — {规则描述，例如："所有外部输入必须经过 validateInput() 处理，绕过会导致下游类型断言失败"}
- `{文件:行号}` — {另一条约束}

## 设计意图

{从代码结构中推断出的模块组织思路。帮助 AI 理解"为什么这么写"，避免新代码风格割裂。}

{例如："该模块将数据获取与业务逻辑严格分层，fetcher 只负责 IO，transformer 不发起任何请求。新增功能时应遵循这一分工，不要在 transformer 层引入 IO 操作。"}

## 扩展路径

{新增某类功能的具体步骤，基于模块中现有的真实例子，不泛泛描述}

**新增 {X}**（参考 `{现有同类文件路径}`）

1. 在 `{目录}` 下创建 `{命名规则}` 文件，实现 `{接口或基类}`（见 `{文件:行号}`）
2. 在 `{注册或入口文件}` 中添加对应入口（见 `{文件:行号}` 中现有写法）
3. {其他必要步骤}

## 风险点

{每条一行，标签四选一：[技术债] / [隐式假设] / [副作用] / [测试盲区]}

- `{文件:行号}` — [技术债] 现象：{描述} / 原因：{为什么存在} / 风险：{改动后果}
- `{文件:行号}` — [隐式假设] {假设内容，违反后的后果}
- `{文件:行号}` — [副作用] {函数/模块除返回值外还做了什么，调用方需感知}
- `{文件或模块}` — [测试盲区] {无覆盖范围描述，改动时需手动验证的内容}

## 文件联动

修改某个文件前，先找到实际依赖它的文件：

```bash
grep -rn "from '.*{目标文件相对路径}'" {模块根}/ --include="*.{ext}"
```

找到依赖文件后，读取并确认它们如何引用了被修改的部分（类型、函数签名、注册入口等），判断是否需要同步更新。
```
